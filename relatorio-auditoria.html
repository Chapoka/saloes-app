4. Vulnerabilidades de Segurança

4.1 Crítico

#VULNERABILIDADELOCALIZAÇÃODETALHES
C-1 Service Role Key como bypass de autenticação server/index.js:36 O token SUPABASE_SERVICE_ROLE_KEY é aceito como Bearer token. Qualquer pessoa com a chave ignora toda autenticação e RBAC.
C-2 Credenciais em plaintext no disco .env.local, server/.env Service role key JWT em texto puro. Pode ter sido commitado ao version control.
C-3 CORS configurado para permitir todas as origens server/index.js:18 cors({ origin: true }) reflete a origem do request — qualquer site pode fazer chamadas autenticadas à API.
C-4 Senhas armazenadas em texto puro no banco server/routes/auth.js:150-155 Campo temp_password armazena a senha em plaintext na tabela users. Se o banco for comprometido, todas as senhas temporárias ficam expostas.

6. Melhorias de Performance

6.1 P0 — Crítico

6.1.1 Zero Code Splitting

Todas as 20 páginas são importadas de forma síncrona em pages.config.js. Nenhum uso de React.lazy() ou Suspense.

Impacto: Bundle único de ~1.2MB (dist/assets/index-BMl-5AQE.js = 1.206.884 bytes). Todo usuário baixa código de TODAS as páginas na primeira visita.

Fix: Converter imports em pages.config.js para React.lazy().

6.1.1 Vite sem otimizações de build

vite.config.js não configura: manualChunks (separar vendors), build.target (navegadores modernos), cssCodeSplit.

6.1.3 18 dependências pesadas não utilizadas

Pacotes como three (~600KB), moment (~300KB), framer-motion (~100KB), lodash (~70KB) aumentam o bundle mesmo com tree-shaking.

6.2 P0 — React

6.2.1 Zero uso de React.memo

Nenhum dos 80+ componentes é otimizado com React.memo. Componentes re-renderizam desnecessariamente.

6.2.2 Computações custosas sem memoização no Dashboard

Dashboard.jsx:120-177 — companyStats itera companies × customers × invoices a cada render (complexidade O(n×m×k)).

6.2.3 DayCalendar com complexidade O(n²×m)

DayCalendar.jsx:30-89 — customers.find() dentro de loops múltiplas vezes para o mesmo customer ID.
